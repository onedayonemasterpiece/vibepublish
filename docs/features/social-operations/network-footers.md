# Сетевые ссылки в подвале публикаций

**Статус требования:** Fixed (решения владельца от 2026-10-09 и 2026-10-10).

Уточнение 2026-10-10: первый пункт каждого существующего автоматического подвала — **Подписаться**, ссылка на текущее назначение в текущей платформе. Далее тот же разделитель и существующие перекрёстные ссылки в прежнем порядке. Охват маршрутов не расширяется. URL текущего Telegram-канала берётся из подтверждённого `handle` активной привязки или существующего проверенного реестра; MAX — из проверенного публичного реестра. Отсутствие публичного URL блокирует план явной ошибкой `network_footer_source_url_unavailable`, без подстановки имени или внутреннего ID. Уже имеющаяся концевая навигация пересобирается в одну строку: текущая ссылка первой, без повторов адресов. Основной текст и опубликованные ранее посты не изменяются. Отдельный backend дайджестов eventsbot сохраняет собственную навигацию для маршрутов вне этого списка; второй подвал VibePublish к ним не добавляет.
**Состояние реализации:** Not confirmed by user — необходима приёмка фактической публикации после CI и развёртывания.

## Маршрутизация

Подвал добавляется только в новые **оригинальные посты владельца** на перечисленных источниках; это не отдельная публикация и не содержимое, сочиняемое моделью.

| Источник | Ссылки, порядок слева направо |
| --- | --- |
| Telegram «Полюбить Калининград» (`lovekenig_tg`) | ВКонтакте → VK «Полюбить Калининград» (`lovekenig_vk`) |
| Telegram «Полюбить Калининград Афиша» (`tg_74cd62f2688ba88ab5fd`) | ВКонтакте → VK «Полюбить Калининград Афиша» (`vk_972b45c6f71c0f2a1fb9`) · MAX → «Полюбить Калининград Анонсы» |
| Telegram «Полюбить Калининград Анонсы» (`tg_5060f37d74cf460135ee`) | ВКонтакте → VK «Полюбить Калининград Анонсы» (`vk_027d33367c33ba2599ee`) · MAX → «Полюбить Калининград Анонсы» |
| MAX «Полюбить Калининград Анонсы» (`max_lovekenig_announcements`) | ВКонтакте → VK «Полюбить Калининград Афиша» (`vk_972b45c6f71c0f2a1fb9`) · Телеграм → «Полюбить Калининград Анонсы» (`tg_5060f37d74cf460135ee`) |

Итоговый вид после основного текста, с пустой строкой сверху:

```text
Подписаться  ·  ВКонтакте  ·  MAX
```

Или для MAX:

```text
Подписаться  ·  ВКонтакте  ·  Телеграм
```

В таблице перечислены перекрёстные ссылки; перед ними всегда добавляется «Подписаться» на текущее назначение.

Все подписи — кликабельные **скрытые ссылки**, без длинных URL в тексте. Между подписями используются два пробела, средняя точка `·`, два пробела. Для односсылочного подвала разделитель не ставится.

## Контракт компилятора

- Источник определяется **устойчивым alias подтверждённой привязки**, не сравнением строк с названием канала.
- Указанные целевые VK-сообщества берутся из собственных активных привязок назначения; канонический `https://vk.com/club<id>` остаётся стабильным при смене публичного имени сообщества. Не использовать `vk.ru/im/channels/...`: это путь к другому разделу, не требуемое сообщество.
- Публичные маршруты Telegram `https://t.me/kenigevents` и MAX `https://max.ru/channel_kenigevents` закреплены в реестре приложения; активные привязки платформ и существование назначения проверяются при сборке плана. При недоступном назначении *не публиковать* неполный или ошибочный подвал.
- Вызов производится после `emojis.compile`, непосредственно в `Application._plan` перед записью неизменяемого `content_json` в редакцию и попытку доставки. Модель пишет только редакционный материал и не вставляет сетевой подвал самостоятельно.
- Ссылки — типизированные `text_link` с корректными UTF-16-смещениями: `telegram_entities` для Telegram, `max_entities` для MAX. Исходные смысловые выделения, эмодзи и их привязки сохраняются.
- Если уже есть ссылки на тот же целевой адрес в **концевой навигационной строке**, они распознаются по URL, а не по совпадению текста и пробелов: повторные не добавлять. Текстовые упоминания в основном содержимом не считаются готовым подвалом.
- При превышении провайдерского ограничения в том числе для подписи к медиа приёмка возвращает ясную ошибку; ни основной текст, ни ссылки молча не отбрасываются.
- Нативная пересылка, редактирование/удаление существующего поста, запланированная публикация другого типа, ответы, реакции, истории VK, Telegram-медиабанк, партнёрские операции и все не перечисленные каналы — без дополнительного подвала. При нативно отложенном **новом** посте подвал замораживается в первоначальном плане до попадания в очередь провайдера.

## Проверка

Регрессии: `tests/runtime/test_network_footers.py` — четыре маршрута с текущим назначением первым, отсутствие публичного URL, неизменность VK и внешнего MAX-подвала eventsbot, семантические ссылки, отсутствие дублей при повторной сборке, сохранение форматирования и UTF-16, медиа/лимиты, отсутствие воздействия на остальные каналы, подготовка итогового `content_json` в реальном сервисном плане. Живую публикацию в качестве теста без редакционного материала не создавать.
