# Предложения стори-каруселей в сторонние сообщества VK

**Требования: Fixed (поручение владельца 10 ноября 2026). Реализация: Not done / Not confirmed by user до включения в рабочий MCP и живого E2E.**

## Пользовательский сценарий

Владелец выбирает уже опубликованную в своём привязанном VK-паблике карусель (её свежую `item_ref` из `vibepublish_read({query:{kind:"item",item_ref:"https://vk.com/wall-..._..."}})`), выбирает целевой **публичный паблик** и видит текст, последовательность фото и предварительный результат. Отдельная команда `vibepublish_vk_proposals` поддерживает `preview`, `submit` и `list`. История **исходящих** предложений не смешивается с опубликованными постами, отложенной очередью или чужой административной «предложкой».

Первый предполагаемый адресат: [«Это Кёниг, детка!»](https://vk.com/eto_koenig); его числовой VK ID должен быть получен из достоверного `groups.getById`, а не угадан по короткой ссылке. Предпросмотр **не отправляет** запись и работает даже до подключения личного VK-токена; действительность адресата и право отправителя проверяются при `submit`. Реальная отправка допускается только после явного отдельного вызова `submit` с устойчивым `request_key`; из готовой карусели можно повторно предложить её другому паблику, а повтор запроса с тем же ключом не создаёт новый пост.

## Границы и гарантии

- Отправитель — **VK user token с правом wall**; токен сообщества не подходит. VK ID OAuth-токены могут не поддерживать `wall.post`, и это не обходится сменой API либо чужими учётными данными.
- Цель — только **публичная страница VK** (type=`page`, is_closed=0), где пользователь **не администратор**. Для иных типов/прав публикация вместо предложения потенциально публичная, поэтому её запрещаем.
- Источник — одна **опубликованная** запись собственного привязанного VK-паблика, содержащая от 2 до 10 упорядоченных изображений. Прямые native photo refs переиспользуются с исходного поста. Если VK не позволит использовать их при отправке, это ошибка; код не должен молча заменять их ссылкой/репостом или редактировать источник.
- `wall.post(owner_id=-id,from_group=0,guid=...)` используется отдельно от штатного `VKAdapter.publish`, в котором требуется право администратора. Параметр `primary_attachments_mode=carousel` должен проходить реальное тестирование с конкретным пабликом.
- Ответ `post_id` подтверждает **приём VK**, но **не публикацию администратором**. Нельзя показывать «опубликовано», пока для этого нет независимого подтверждения. Недоступность чужой очереди для чтения не меняет результат отправки.
- Если ответ VK потерян после отправки, статус остаётся **исход неизвестен**; нельзя делать новый запрос с другим ключом. История привязана к оригинальному `operation_id` и проверяется через `vibepublish_status`.
- Записи доступны только владельцу, в его tenant/principal; токены никогда не передаются в MCP, журнал или диагностические сообщения. Ни одного тестового предложения на чужую стену без реального пользовательского токена и проверки типа/пользовательских прав.

## Приёмка и эксплуатация

Проверить исходник и число/порядок карточек по точному опубликованному wall-посту, сухой `preview`, отказ на group-token, отказы при административных правах/закрытом или обычном сообществе, два `submit` с одним ключом, VK-квитанцию и `list` после рестарта. Проверить смартфон и десктоп для той поверхности интерфейса, которая реально развёрнута. Проверить, что VK270/259 share, существующие опубликованные карусели и их редактирование не меняются. Подтверждённая отправка в конкретный сторонний паблик и его решение об одобрении — **отдельные** критерии.
