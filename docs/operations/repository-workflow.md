# Repository Workflow

Status: `Fixed`

- Check `git status` before staging or committing.
- Stage only files directly related to the current task.
- Do not commit `.env`, secrets, caches, build output, or `artifacts/`.
- Keep docs and `CHANGELOG.md` synchronized with durable changes.
- Once a remote exists, push durable completed work unless the user says not to.

## Proof of GitHub delivery

- Discover the actual file/tree/commit/ref actions and read the current branch.
  A filtered action list or historical per-call failure does not establish a
  permanent read-only repository. Use a useful, authorized write as the proof.
- Report separately: accepted tree, created commit, updated branch and readback.
  An unreferenced tree or local archive is not delivered source.
- Classify a current response precisely: version conflict, GitHub authorization,
  conversation routing, or request safety evaluation. Preserve a current safety
  block; do not change routes, encodings or agents to obtain the denied effect.
- Do not claim full delivery until the intended file set and content hashes
  match the remote tree. A partial checkpoint must remain explicitly non-release.
